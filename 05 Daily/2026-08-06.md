## brain.py stream-limit crash — 2026-08-06

- The Phase 4 "brain line-limit fix" (`limit=2**20`) turned out to be **incomplete**. A raised limit still raises `ValueError` once a line clears the new ceiling, and there was no handler — so `ask()` died inside its fire-and-forget `create_task()`: silent chat, no traceback, no `done` sentinel.
- Real fix in `jarvis/services/brain.py`: `iter_lines()` skips oversized lines and keeps reading (`readline()` drains before raising); `ask()` wraps everything in `try/except/finally`, broadcasts a friendly error, and always emits `done: True`. Also drained `stderr` concurrently — an unread `stderr=PIPE` would have deadlocked a chatty reply.
- Reproduced the exact reported error against a real subprocess and confirmed recovery. 4 new tests. Commit `852ebf9`; **20 passing** (the other 2 came from the graph-tab work in `f2efe9c`, committed by a concurrent session at 20:20).
- Full writeup in [[Debug Log]].

## Jarvis memory wiring — 2026-08-07

- **Root cause found:** the brain spawned `claude` with no `cwd`, so it ran in the `jarvis-hud` repo and never saw the vault's `CLAUDE.md`, notes, or memory protocol. Fixed by running the subprocess with `cwd=VAULT_PATH`. The whole protocol then loads for free — no reimplementation needed.
- **Write access:** `--permission-mode acceptEdits --allowedTools "Read,Write,Edit,Glob,Grep"`. **Bash deliberately withheld** — a voice assistant acting on a misheard phrase must not get a shell.
- **Conversation memory:** every turn used to be amnesiac (fresh subprocess, no recall of the previous sentence). Now captures `session_id` from the stream and passes `--resume`. A failed turn drops the session so a bad id can't poison every future turn.
- **Boot:** `jarvis/services/boot.py` runs the CLAUDE.md session-start protocol on startup (Standing Instructions → About Mackenzie → today's note), then greets aloud. Takes ~14s.
- **Verified live:** read rule 5 correctly; remembered the prior turn; and on being corrected about time format, appended it to Working Style *and* bumped the `updated:` frontmatter — unprompted, following the protocol.
- Logging now configured in `run.py` (was silently dropping everything, incl. `ears: heard ...`). Commit `5342add`, 40 tests passing.

## Voice input: open-mic → push-to-talk — 2026-08-07

- Automatic endpointing kept cutting me off mid-sentence. Claude tuned the silence threshold three times (0.6s → 1.5s → 2.0s) and added hysteresis (separate start/continue thresholds), and it still interrupted. It admitted it could not reproduce the failure and was guessing.
- **Switched to push-to-talk.** Hold `SPACE` (or hold the button) to talk, release to send. Releasing *is* the end of the turn, so there is no silence threshold, no hysteresis, and nothing to guess — the entire class of bug is gone rather than tuned around.
- Extras: 0.3s pre-roll captured before the key goes down (so reaction time doesn't clip the first syllable); pressing the key while Jarvis is talking interrupts him; key auto-repeat can't double-trigger; releasing focus can't leave the mic stuck open.
- **Lesson:** when a heuristic needs its third round of tuning and the failure can't be reproduced, remove the guess instead of refining it. Commit `368f191`, 47 tests passing.

## Jarvis file access + shell — 2026-08-07

- Jarvis can now read/edit **`C:\Users\Mackenzie`** (all my files) and **`C:\Users\Mackenzie\jarvis-hud`** (its own source), via `--add-dir`. Deliberately **not** the `C:\` root — Windows system files and Program Files stay out of reach of something driven by speech that can be misheard.
- **Shell is an allowlist, not a blanket grant:** only `pytest`, `python -m pytest`, `git status/diff/log/add/commit`. Headless mode can't raise an interactive permission prompt, so the allowlist *is* the enforcement — `rm`, `del`, `format`, `git push`, `curl` etc. simply cannot run however a phrase is misheard. On top of that the prompt requires it to say what it wants to run and wait for my yes.

- **Self-editing caveat:** changes to its own code need a restart, and a syntax error there means it won't start. Prompt tells it to say so when it edits itself.
