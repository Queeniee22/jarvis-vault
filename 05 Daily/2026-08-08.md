# 2026-08-08

- jarvis-hud graph tab: replaced the mock node/link fallback in `static/js/graph.js` with a real loading spinner ("loading graph…") so it no longer looks like live data when there isn't any. Verified working in browser.
- Doing so exposed a real bug: the graph tab now spins forever because `vault.run()` in `jarvis/services/vault.py` never gets past its `OBSIDIAN_API_KEY` check, so it never broadcasts real graph data. See [[Debug Log]] for the diagnosis.
- Continuing this in the Claude desktop app — pick up from confirming the env var and restarting the server.
- Rewrote `ConnectionHub` (`jarvis/hub.py`): one queue + one writer task per socket instead of a shared lock, catch-up queued inside `hub.add()`, backlog collapses to newest-state-per-type on overflow. Rationale in [[Jarvis HUD Design]] under Graceful degradation. 68 tests pass; verified over real TCP that a late-connecting browser gets the calendar-offline notice.
- **The graph-tab diagnosis above was wrong.** `OBSIDIAN_API_KEY` *is* set (64 chars), so `vault.run()` takes the looping path, not the bail-out. Probed every boundary: Obsidian REST API on 27126 answers 200, `list_files()` → 22 files, `build_graph()` → 22 nodes / 56 links. The vault was never broken. The spinner was the *same* bug as the calendar one — the graph is broadcast ~1.7s after startup, before the browser connects, and the old hub had no memory of it, so the page waited up to 60s for the next cycle. Fixed by the hub catch-up.
- Made a vault outage actually visible, since the design promises independent degradation: `applyStatus()` in `static/js/hud.js` now handles vault as well as calendar, and `static/js/graph.js` gained a notice mode so the canvas says "vault offline — <reason>" instead of spinning a lie. Real data clears it, so it self-heals on the next 60s cycle. Verified in a browser against a real server both ways: offline → canvas draws the notice with zero spinner arcs; online → 22 nodes / 56 edges painted.
- Left alone: `#vaultList` in `static/index.html` still ships hardcoded placeholder rows, now overwritten on the first status or vault message either way. `ears`/`voice` offline statuses are still console-only — no panel for them yet.
