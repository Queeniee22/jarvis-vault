# 2026-09-08

- **Vault is now a git repo**, replacing Obsidian Sync. Sync is paid; a private GitHub remote is free, versioned, and not a vendor. Two repos rather than one, so the journal isn't welded to code that might one day be public: `jarvis-vault` and `jarvis-hud`. Full procedure in [[Setup — Claude Code Connection]].
- **Found a live secret leak before it could reach GitHub.** The Obsidian Local REST API key was hardcoded in plaintext in both `connect-jarvis.ps1` (line 6) and `fix-mcp-config.ps1` (line 16). Both now read `OBSIDIAN_API_KEY` from the environment, falling back to `.env.local` at the vault root, which is gitignored. Fixed *before* `git init` — a key committed even once stays recoverable through `git log -p` forever, so the ordering was the whole point. Originals with the key intact are in `.secrets-backup/` (also gitignored).
- Also excluded `.obsidian/plugins/` — the Local REST API's `data.json` holds that same key **plus the CA private key** that [[Setup — Claude Code Connection]] already warned about trusting machine-wide. And `.obsidian/workspace.json`, which is just which panes are open and would conflict on every single sync.
- Audited `jarvis-hud` before pointing it at a remote: 56 commits, and no `.env`, `token.json`, or `credentials.json` was ever committed — only `.env.example`. Its `.gitignore` was correct from the start. Nothing to scrub.
- Added `.gitattributes` (`text=auto eol=lf`, CRLF for `.ps1`) so two Windows machines don't produce whole-file diffs on every note.
- Corrected a stale line in [[Setup — Claude Code Connection]]: it said auth lives in `data.json`. Still true for Obsidian itself, but the scripts' canonical source is now `.env.local`.
