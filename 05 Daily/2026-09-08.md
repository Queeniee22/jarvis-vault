# 2026-09-08

- **Vault is now a git repo**, replacing Obsidian Sync. Sync is paid; a private GitHub remote is free, versioned, and not a vendor. Two repos rather than one, so the journal isn't welded to code that might one day be public: `jarvis-vault` and `jarvis-hud`. Full procedure in [[Setup — Claude Code Connection]].
- **Found a live secret leak before it could reach GitHub.** The Obsidian Local REST API key was hardcoded in plaintext in both `connect-jarvis.ps1` (line 6) and `fix-mcp-config.ps1` (line 16). Both now read `OBSIDIAN_API_KEY` from the environment, falling back to `.env.local` at the vault root, which is gitignored. Fixed *before* `git init` — a key committed even once stays recoverable through `git log -p` forever, so the ordering was the whole point. Originals with the key intact are in `.secrets-backup/` (also gitignored).
- Also excluded `.obsidian/plugins/` — the Local REST API's `data.json` holds that same key **plus the CA private key** that [[Setup — Claude Code Connection]] already warned about trusting machine-wide. And `.obsidian/workspace.json`, which is just which panes are open and would conflict on every single sync.
- Audited `jarvis-hud` before pointing it at a remote: 56 commits, and no `.env`, `token.json`, or `credentials.json` was ever committed — only `.env.example`. Its `.gitignore` was correct from the start. Nothing to scrub.
- Added `.gitattributes` (`text=auto eol=lf`, CRLF for `.ps1`) so two Windows machines don't produce whole-file diffs on every note.
- Corrected a stale line in [[Setup — Claude Code Connection]]: it said auth lives in `data.json`. Still true for Obsidian itself, but the scripts' canonical source is now `.env.local`.

- **Both repos are live on GitHub, private**, under `Queeniee22`. The first attempt was blocked — that account sat under an org policy that greys out the Private option. Mackenzie resolved it on his end. Worth remembering: this vault holds a journal and named people, so it must never land on an employer- or school-managed account.
- Git Credential Manager was already installed and set system-wide (`credential.helper = manager`), so no SSH key or personal access token was needed. Push just worked.
- `jarvis-hud` was on `master` while the vault was on `main`. Renamed to `main` before the first push, which is free while no remote exists. The stale `fix/hub-state-delivery` branch is fully merged (0 unique commits) and stayed local; delete it whenever.
- Verified against the *remotes* rather than trusting the local gitignore: 47 files on `jarvis-vault`, 54 files / 56 commits on `jarvis-hud`, and no `.env`, `.env.local`, `token.json`, `credentials.json`, `.obsidian/plugins/`, or `.secrets-backup/` on either.

**Second machine is a Mac — ported both repos**

- The hardcoded `C:/Users/Mackenzie/...` in `.claude/launch.json` is **gone**, and the fix was better than the one I planned. Rather than a path per machine, both paths are now *relative*: the vault reaches the HUD through `../jarvis-hud`, which is correct on both machines because the two repos are siblings either way. The username variable is eliminated instead of branched on. Verified by actually launching the HUD from the vault directory — uvicorn started, then stopped so nothing was left holding 8770.
- Each `launch.json` now carries two named configurations, `jarvis-hud-windows` and `jarvis-hud-mac`. The venv binary directory (`.venv\Scripts` vs `.venv/bin`) is the only irreducible difference — Python imposes it, so it is the one thing worth duplicating.
- **`connect-jarvis.sh` and `fix-mcp-config.sh`** are new, paired with the existing `.ps1` versions. All four read the key from `$OBSIDIAN_API_KEY` or `.env.local`, none contain it. The `.sh` pair parses the REST API response with `sed`/`grep` rather than a JSON dependency, except `fix-mcp-config.sh`, which uses `python3` because it has to rewrite `~/.claude.json` safely.
- `.gitattributes` in both repos now pins `*.sh` to **LF**. This one matters: a shell script checked out with CRLF fails on macOS with `bad interpreter: no such file or directory`, and the cause is invisible in an editor.
- [[Jarvis HUD Runbook]] and [[Setup — Claude Code Connection]] now give Windows and macOS commands side by side. Added two macOS-specific facts worth keeping: `sounddevice` needs `brew install portaudio`, and a dead mic on macOS is often the *Privacy & Security → Microphone* permission rather than the device.
- **macOS has no Git Credential Manager** — that is Windows-only, and it is why cloning on the Mac needs `gh auth login` first. Also `user.name`/`user.email` are per-machine and do not travel in the repo.
- 132 backend and 56 frontend tests pass after the changes.
